# Agent-X v2.1.0 "Bedrock" — Release Notes

## Overview

Agent-X v2.1.0 hardens the foundation for Phase 2 Memory. This release lands EF Core migrations, SQLCipher at-rest encryption, and an audit log — the crypto and discipline layer the rest of Phase 2 builds on.

## New Features

### EF Core Migrations (B9)

Database schema changes now ship via EF Core migrations under `src/AgentX.Core/Data/Migrations/`. Pre-B9 installs (which used `EnsureCreatedAsync`) are auto-adopted at the `InitialBaseline` migration on first launch so existing user data is preserved.

- `IMigrationRunner.RunAsync()` replaces ad-hoc `EnsureCreatedAsync` + manual `ALTER TABLE` block
- Baseline adoption for pre-migration installs
- `IMigrationRunner.GetPendingMigrationsAsync()` for future UI surfacing
- `AgentXDbContextFactory` design-time factory for `dotnet ef` tooling

### Database Encryption (C13)

Your vault can now be encrypted at rest using SQLCipher 4 (AES-256-CBC).

- **Tier-aware key management**: Starter/Professional use a transparent DPAPI-wrapped key tied to the Windows user; Ultimate tier uses a passphrase with PBKDF2-HMAC-SHA256 (600,000 iterations) derivation
- **Raw-bytes key delivery**: every connection applies the key via `PRAGMA key = "x'<hex>'"` — the `Password=` connection-string shortcut is never used because it silently KDF-derives a different key
- **One-shot plaintext → encrypted migration** via SQLCipher's `sqlcipher_export` with atomic file swap and rollback-on-failure
- **Out-of-DB marker file** at `%LocalAppData%\AgentX\encryption.info.json` breaks the chicken-and-egg of "to check encryption state I must first unlock the DB"
- **Settings UI** to enable encryption with tier-appropriate UX (Ultimate: passphrase dialog; others: transparent enable)
- **Startup unlock flow** reads the marker first, derives the key via `IDatabaseKeyService`, applies it via `AgentXDbContext.EnsureKeyApplied()` before the migration runner touches the DB
- Wrong-passphrase recovery loop with SQLite ErrorCode-26 detection

Disabling encryption is not supported in v2.1 — restore from a pre-encryption backup to revert.

## Breaking Changes

None for users on Starter / Professional / Ultimate who do not enable encryption. Users who enable encryption will have their database atomically converted on toggle; a `.plain.bak` backup of the plaintext database is retained only through the atomic-swap critical section and removed on success.

## Upgrade Notes

- First launch after upgrade will adopt the `InitialBaseline` migration automatically — no action needed
- Encryption is opt-in. If you enable it and later forget your passphrase (Ultimate tier), the database cannot be recovered — back up first via Settings → Backup & Restore

## Known Issues

- Test-host shutdown hang (`H1`): the xUnit test host does not exit cleanly after all tests pass due to native library handles (SQLitePCLRaw / Whisper.Net / LLamaSharp). Tests themselves all pass in ~6 seconds; blame-hang timeout of 30s can be used for CI runs. Fix tracked as Phase 1 hardening ticket.
- `dotnet ef migrations add` on this project requires `-p:CopyLocalLockFileAssemblies=true` due to the `net8.0-windows10.0.22621.0` target omitting runtime packs from the build output. Pre-build with that flag, then invoke `dotnet ef ... --no-build`.
