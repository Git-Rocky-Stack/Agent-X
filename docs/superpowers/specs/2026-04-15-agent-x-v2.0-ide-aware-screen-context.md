# Agent-X v2.0 — IDE-Aware Screen Context Enhancement

**Date:** 2026-04-15
**Feature:** Enhancement to #12 — Screen Awareness
**Priority:** P1
**Effort:** Small-Medium (1-2 days)
**Depends On:** Screen Awareness (v2.0 — COMPLETE)

---

## 1. Problem Statement

Screen Awareness captures OCR text from any window, but when the user is working in an IDE (VS Code, Visual Studio, JetBrains, Cursor), the OCR output is unstructured. The AI doesn't know:
- Which IDE is active
- What file the user is editing
- What programming language the code is in
- What project/workspace is open

This means the AI treats IDE screen text the same as a Notepad window — no context about the development environment.

## 2. Solution

Enhance `ScreenContextResult` with structured IDE context extracted from the active window title. IDEs embed rich metadata in their window titles (filename, project name, IDE identifier). Parse these patterns to create structured context that the AI system prompt can use intelligently.

**No external dependencies. No installer changes. Pure string parsing of data we already capture.**

### Architecture

```
Win+Shift+A hotkey
    │
    ▼
QuickChatViewModel.SubmitQueryAsync()
    │
    ├── ScreenCaptureService.CaptureActiveWindowAndOcrAsync()
    │       │
    │       ├── GetActiveWindowTitle() ──► raw title string
    │       │                              │
    │       │                              ▼
    │       │                    IdeWindowDetector.Detect()
    │       │                              │
    │       │                              ├── IdeDetection { IdeName, ActiveFileName,
    │       │                              │                 ProjectName, Language }
    │       │                              │
    │       │                              └── null (if no IDE detected)
    │       │
    │       ├── OCR text from screen capture
    │       │
    │       ▼
    │    ScreenContextResult (enhanced with IdeDetection field)
    │
    ▼
QuickChatViewModel builds system prompt:
    ├── If IDE detected: "--- IDE CONTEXT ---" section with structured fields
    └── Always: "--- SCREEN CONTEXT ---" section with OCR text
```

## 5. IdeDetection Model

```csharp
public class IdeDetection
{
    /// The detected IDE name (e.g. "Visual Studio Code", "Visual Studio 2022", "Rider").
    public string IdeName { get; init; } = string.Empty;

    /// The active file name extracted from the window title (e.g. "Program.cs").
    public string ActiveFileName { get; init; } = string.Empty;

    /// The project or workspace name (e.g. "Agent-X", "my-project").
    public string ProjectName { get; init; } = string.Empty;

    /// The programming language inferred from the file extension (e.g. "C#", "Python").
    public string Language { get; init; } = string.Empty;

    /// The original window title that was parsed.
    public string RawTitle { get; init; } = string.Empty;
}
```

## 6. IdeWindowDetector

Window title patterns per IDE:

| IDE | Title Pattern | Example |
|-----|--------------|---------|
| VS Code | `{filename} - {folder} - Visual Studio Code` | `Program.cs - Agent-X - Visual Studio Code` |
| VS Code (remote) | `{filename} - {folder} [SSH: ...] - Visual Studio Code` | `app.ts - my-app [SSH: dev] - Visual Studio Code` |
| Visual Studio | `{filename} - {solution} - Microsoft Visual Studio` | `Program.cs - Agent-X - Microsoft Visual Studio` |
| Visual Studio (versioned) | `{filename} - {solution} - Microsoft Visual Studio 2022` | `Form1.cs - MyApp - Microsoft Visual Studio 2022` |
| Rider | `{filename} – {solution} – JetBrains Rider` | `Program.cs – Agent-X – JetBrains Rider` |
| IntelliJ IDEA | `{filename} – {project} – IntelliJ IDEA` | `Main.java – my-app – IntelliJ IDEA` |
| Cursor | `{filename} - {folder} - Cursor` | `App.tsx - my-project - Cursor` |
| Zed | `{filename} — Zed` | `main.rs — Zed` |

**Detection rules:**
1. Check window title suffix for known IDE identifiers
2. Split title by ` - ` or ` – ` separators
3. First segment = filename, second segment = project/workspace, last segment = IDE name
4. Infer language from file extension (`.cs` → C#, `.py` → Python, etc.)

## 11. Design Principles

- **Zero external dependencies**: Pure C# string parsing, no new NuGet packages
- **Graceful degradation**: If detection fails, falls back to raw OCR-only context
- **Privacy-preserving**: Only parses window title (already captured), no file system access
- **Minimal footprint**: Two new small files, minor changes to three existing files
- **Backward compatible**: ScreenContextResult.IdeContext is nullable, existing callers unaffected
