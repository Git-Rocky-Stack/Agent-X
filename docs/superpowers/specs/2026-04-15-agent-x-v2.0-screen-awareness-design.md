# Agent-X v2.0 — Screen Awareness Design Spec

**Date:** 2026-04-15
**Feature:** #12 — Screen Awareness
**Priority:** P1 (Competitive parity with ChatGPT/Claude Desktop)
**Effort:** Large (4-6 weeks)
**Depends On:** System Tray + Global Hotkey (v1.4.0 — COMPLETE)

---

## 1. Problem Statement

Users cannot ask Agent-X about what's on their screen. ChatGPT Desktop and Claude Desktop both have screen awareness — this is becoming table stakes for desktop AI. The current Quick Chat overlay (`Win+Shift+A`) sends queries to AI without any screen context.

## 2. Solution

Add optional screen awareness that captures the screen when the user invokes Quick Chat, performs OCR on the capture, and injects the extracted text as context into the AI query. Users control capture scope (full screen, active window) and can disable the feature entirely.

### Architecture

```
Win+Shift+A hotkey
    │
    ▼
SystemTrayService (triggers QuickChatRequested)
    │
    ├── NEW: CaptureScreenAsync() ──► ScreenCaptureService
    │                                       │
    │                                       ├── Windows.Graphics.Capture API
    │                                       └── OcrEngine (existing pattern)
    │                                       │
    │                                       ▼
    │                                    OCR text (or empty)
    │
    ▼
QuickChatViewModel.SubmitQueryAsync()
    │
    ├── Append screen OCR text to system prompt
    │
    ▼

```

## 5. IScreenCaptureService Interface

```csharp
public interface IScreenCaptureService
{
    /// Captures the screen and performs OCR. Returns context result or empty if disabled/failed.
    Task<ScreenContextResult> CaptureAndOcrAsync(CancellationToken ct = default);
    
    /// Captures the active window only (not full screen).
    Task<ScreenContextResult> CaptureActiveWindowAndOcrAsync(CancellationToken ct = default);
}
```

## 6. ScreenContextResult Model

```csharp
public class ScreenContextResult
{
    public string OcrText { get; init; } = string.Empty;
    public string ActiveWindowTitle { get; init; } = string.Empty;
    public DateTime CapturedAtUtc { get; init; } = DateTime.UtcNow;
    public bool IsEmpty => string.IsNullOrWhiteSpace(OcrText) && string.IsNullOrWhiteSpace(ActiveWindowTitle);
}
```

## 7. Implementation Strategy

### Phase 1: Core Service (ScreenCaptureService)
- Use `GraphicsCapturePicker` for first-time consent (unpackaged WinUI 3)
- Capture via `GraphicsCaptureItem.CreateFromInterop` (active window) or full screen
- Render captured frame to `SoftwareBitmap`
- Reuse `OcrEngine.RecognizeAsync()` from `ImageProcessor` pattern
- Extract active window title via `GetForegroundWindow` + `GetWindowText` P/Invoke

### Phase 2: Quick Chat Integration
- Add `IScreenCaptureService` to `QuickChatViewModel` constructor
- On `SubmitQueryAsync`, call `CaptureActiveWindowAndOcrAsync()` if enabled
- Append OCR text to system prompt: "Screen context (captured {timestamp}):\n{ocrText}"
- Show indicator in Quick Chat that screen context was captured

### Phase 3: Settings
- `EnableScreenAwareness` (bool, default: false) — opt-in
- `ScreenCaptureMode` (enum: ActiveWindow, FullScreen, Disabled)

## 8. Privacy Controls

- **Off by default** — user must enable in Settings
- **Per-session** — user can toggle on/off without restarting
- **No auto-save** — captured screen content is NOT written to the knowledge vault
- **Temporary** — OCR text is held in memory only for the current query, then discarded
- **Visual indicator** — Quick Chat shows "Screen context captured" badge when active
- **No recording** — single-frame capture only, no video/audio
