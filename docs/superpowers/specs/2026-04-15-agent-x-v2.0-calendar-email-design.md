# Agent-X v2.0 — Calendar/Email Integration Design Spec

**Feature:** #10 — Calendar/Email Integration (via Plugin API)
**Priority:** P1 — Knowledge hub disconnected from calendar/email
**Effort:** Very Large (6–8 weeks)
**Status:** PLANNING
**Branch:** `feature/calendar-email-integration` (from `main` after HNSW merge)

---

## 1. Problem Statement

Agent-X is a knowledge hub, but it's disconnected from the two systems where users spend the most time: calendar and email. Every competitive product (Reflect, Capacities, Notion AI, ChatGPT) connects to these data sources. Without calendar/email integration:

- Users cannot search meeting context (attendees, agendas, notes) alongside their documents.
- Users cannot triage email into their knowledge vault for AI-powered search and summarization.
- The Smart Inbox is limited to document imports — it cannot receive email or calendar events.
- The Plugin API has no OAuth2 infrastructure, preventing any third-party data connectors.

**This feature bridges the gap** by building OAuth2 infrastructure in the Plugin API and two first-party plugins (Calendar + Email) that sync external data into the vault.

---

## 2. Solution Overview

Four-phase delivery:

| Phase | Deliverable | Weeks |
|-------|-------------|-------|
| **Phase 1** | OAuth2 Infrastructure (Plugin API extension) | 1.5 |
| **Phase 2** | Calendar Connector Plugin (Outlook + Google Calendar) | 2 |
| **Phase 3** | Email Connector Plugin (Outlook + Gmail) | 2 |
| **Phase 4** | Search Integration + Vault Indexing | 1.5 |

**Key architectural decisions:**
- OAuth2 tokens stored DPAPI-encrypted in SQLite — no passwords ever stored.
- Calendar/Email plugins are **first-party** `IPlugin` implementations using the existing Plugin API.
- Synced data flows through `InboxItemEntity` → `DocumentEntity` pipeline (reuse existing indexing).
- New `PluginType.DataConnector` enum value for plugins that bring external data into the vault.
- New `IOAuthService` interface registered in the plugin-scoped DI container.
- Per-calendar/per-folder sync scope for privacy controls.

### 4.4 DPAPI Token Encryption

OAuth tokens are encrypted using Windows DPAPI before storage in SQLite. This reuses the existing DPAPI infrastructure from Feature #1 (v1.4):

```csharp
public class OAuthService : IOAuthService
{
    private readonly AgentXDbContext _dbContext;
    private readonly ILogger _log;
    private readonly OAuthSettings _settings;

    // DPAPI encryption (same approach as DPAPI key encryption in v1.4)
    private string EncryptToken(string plainToken)
    {
        byte[] plainBytes = Encoding.UTF8.GetBytes(plainToken);
        byte[] encrypted = ProtectedData.Protect(plainBytes, null, DataProtectionScope.CurrentUser);
        return Convert.ToBase64String(encrypted);
    }

    private string DecryptToken(string encryptedToken)
    {
        byte[] encryptedBytes = Convert.FromBase64String(encryptedToken);
        byte[] plainBytes = ProtectedData.Unprotect(encryptedBytes, null, DataProtectionScope.CurrentUser);
        return Encoding.UTF8.GetString(plainBytes);
    }
}
```

### 4.5 Localhost OAuth Callback

OAuth2 requires a redirect URI. The app spins up a lightweight `HttpListener` on localhost to receive the callback:

- Google: `http://localhost:8400/oauth/callback`
- Microsoft: `http://localhost:8401/oauth/callback`

The `OAuthBrowserAuth` class opens the system browser for the consent screen, then listens for the redirect on the localhost port. When the callback arrives, it exchanges the auth code for tokens and closes the listener.

### 4.6 Token Refresh

`OAuthService.GetAccessTokenAsync()` automatically refreshes expired tokens:

1. Check `TokenExpiry - RefreshBufferMinutes < now`
2. If expired, call `RefreshTokenAsync()` using the stored refresh token
3. Update `AccessToken`, `RefreshToken` (may change), and `TokenExpiry` in DB
4. Return the fresh access token

If refresh fails (revoked, expired), the service returns `null` and the plugin should prompt re-authorization.

### 5.3 Sync Flow

1. `CalendarSyncService` runs on a configurable timer (default 15 min).
2. For each enabled calendar, call `ICalendarProvider.GetEventsAsync()` with delta token for incremental sync.
3. New/updated events pass through `CalendarEventProcessor.ConvertToInboxItem()`.
4. `InboxService.TriageAsync()` processes each item:
   - Convert to `ProcessedDocument` via `DocumentService`.
   - Chunk via `ChunkingService`.
   - Embed via `EmbeddingService`.
   - Store via `HnswVectorStore` (or `SqliteVecStore` for small vaults).
5. Sync result (new count, updated count, errors) logged and surfaced to Plugin Manager UI.

### 5.4 Privacy Controls

Users can choose which calendars to sync:
- Google: All calendars the user has read access to.
- Outlook: All calendars in the user's mailbox.

Each calendar shows: Name, Owner, Event count, Last synced. Toggle on/off per calendar.

## 9. Search Integration

### 9.1 Calendar Events in Search

Calendar events are indexed like documents:
- Title → document title
- Description + attendees + location → chunked content
- Start/End time → metadata fields
- SourceProvider → `"google-calendar"` or `"outlook-calendar"`

Search results show calendar events with a distinct icon and "Calendar" source badge.

### 9.2 Email Messages in Search

Email messages are indexed like documents:
- Subject → document title
- Body text → chunked content
- From/To/Cc → metadata fields
- Category → tag for filtering
- SourceProvider → `"gmail"` or `"outlook-email"`

Search results show emails with envelope icon and category badge.

### 9.3 RAG Integration

Calendar and email content is available in RAG queries alongside documents:
- "What meetings do I have with Sarah this week?" → searches calendar events
- "What did John email me about the Q3 report?" → searches emails
- "Find all discussions about the product launch" → searches both + documents

The `SemanticSearchService` already handles `InboxItemEntity`-sourced documents — calendar and email items flow through the same pipeline.

## 15. Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| OAuth2 provider API changes | High | Low | Pin API versions, abstract provider interfaces, comprehensive error handling |
| DPAPI encryption fails on some Windows versions | High | Low | Fallback to base64 encoding with warning log; test on Win10/Win11 |
| Google/Microsoft rate limits | Medium | Medium | Exponential backoff, configurable sync intervals, respect X-RateLimit headers |
| Token refresh race conditions | Medium | Low | SemaphoreSlim on refresh, single writer pattern, compare-and-swap DB updates |
| Large email sync overwhelms vault | Medium | Medium | Pagination (MaxMessagesPerSync), backpressure on DocumentService, progress reporting |
| Plugin isolation breaks OAuth flow | High | Low | OAuth flow runs in host process, only tokens passed to plugin; plugin never handles browser |
| Calendar event duplication | Medium | Medium | ExternalId deduplication, idempotent sync, delta token tracking |
| Background sync drains battery | Low | Medium | Configurable intervals, sync pauses on battery saver, respect Windows power throttling |
