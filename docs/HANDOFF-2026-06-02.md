# Session Handoff — 2026-06-02 — Security Audit Remediation

This session remediated the security findings in `AGENTX_AUDIT_FINDINGS.md` that **failed the
Codex review gate**, plus the backup authenticated-encryption hardening, the extension npm-audit
vulnerabilities, and a required follow-up to keep the mobile companion working. Branch:
**`security/audit-remediation`** (off `main`), two commits.

---

## TL;DR

- ✅ **#1 Critical — unauthenticated local API + wildcard CORS:** the `localhost:9846` REST API now
  requires a per-install **bearer token** on every route except the extension health probe, the
  token is **DPAPI-encrypted** at rest, CORS echoes the origin **only** for `chrome-extension://` /
  `moz-extension://` (web pages get no `Access-Control-Allow-Origin`), and a Settings toggle gates
  startup. The browser extension pairs via a pasted token; desktop **Settings → Connections**
  shows/copies/regenerates it.
- ✅ **#2 High — backup ZIP path traversal:** new `PathHelper.ResolveContainedPath` containment
  guard enforced in both `ValidateBackupAsync` and the restore loop, plus per-entry/total expansion
  caps (zip-bomb).
- ✅ **#3 High — weak plugin manifest/path validation:** the strict `PluginManifestValidator` is now
  wired into install and tightened (reverse-DNS ID, bare-`.dll` entry assembly); containment guards
  added to install-path, activation load, and uninstall delete.
- ✅ **#4 Medium — `WebSearchApiKey` plaintext:** now DPAPI-encrypted + auto-migrated like the other
  provider secrets.
- ✅ **#5 Med/Low — web-fetch size-cap bypass:** bounded streaming read enforces the 10 MB cap even
  when `Content-Length` is absent/dishonest.
- ✅ **Backup AEAD (scope add):** backups now use **AES-256-GCM** authenticated encryption (V2);
  legacy AES-256-CBC archives still restore.
- ✅ **Extension npm audit:** `npm audit fix` + `copy-webpack-plugin@14` → **0 vulnerabilities**.
- ✅ **Mobile follow-up:** `AgentX.Mobile` now sends the bearer token (stored in `SecureStorage`)
  and has a pairing field, so it isn't locked out by the new auth.

**Verification:** `AgentX.Tests` **1875 passed / 0 failed / 2 skipped** (browser-only);

## Approach

Findings were **re-confirmed against the live code** before any fix (the audit's claims were
verified, not trusted), then fixed root-first with a **failing-test → fix → verify** loop using the
repo-pinned **.NET 8.0.421 SDK** at `C:\Users\Rock\.dotnet` (the original auditor couldn't run tests
because the system PATH only had .NET 10). Three product decisions were taken with Rocky up front:

1. **Extension auth model →** per-install DPAPI token, **paste-to-pair** (vs. a `/pair` handshake or
   Chrome native messaging).
2. **API startup →** **auto-start but authenticated**, with a Settings toggle to disable (vs. opt-in).
3. **Backup encryption →** **do the AEAD upgrade now**, backward-compatible with legacy CBC backups.

## 1. Local REST API authentication + CORS (#1, Critical)

New **`src/AgentX.Core/Services/Api/LocalApiSecurity.cs`** — pure, `HttpListener`-free policy so the
security decisions are deterministic and unit-testable:
- `IsAuthorized(authHeader, expectedToken)` — bearer parse + **constant-time** compare
  (`CryptographicOperations.FixedTimeEquals`), **fails closed** when no token is provisioned.
- `ResolveAllowedOrigin(origin)` — returns the origin only for `chrome-extension://` /
  `moz-extension://`; web origins return `null` (→ no ACAO header).
- `IsPublicPath(path)` — only `/api/extension/health` (returns no user data).
- `GenerateToken()` — 256-bit, hex.

`ApiHostService`: computes the request path once, enforces auth on every non-public route (401 +
`WWW-Authenticate: Bearer`), and `WriteCorsHeaders(resp, origin)` now scopes the ACAO to the
resolved origin. The token is held in a field set at `StartAsync(port, authToken, ct)` — the
`IApiHostService` contract gained the `authToken` parameter.

`ApiHostLifecycleService` now depends on `ISettingsService`: it skips startup when
`AppSettings.LocalApiEnabled` is false, **mints + persists** a token on first start, and passes it
to the host. `AppSettings` gained `LocalApiEnabled` (default `true`) and `LocalApiToken`
(DPAPI-encrypted in `SettingsService`, same path as the other secrets).

**Desktop UI:** `SettingsPage.xaml` gained a **Connections** card (enable toggle + token field with
**Copy** / **Regenerate**); `SettingsViewModel` loads/saves the two fields and adds
`CopyApiTokenCommand` / `RegenerateApiTokenCommand`. (Literal strings, matching the rest of the page
→ no `x:Uid`/`.resw` churn → LocaleAudit unaffected.)

**Extension:** `agentx-api.ts` sends `Authorization: Bearer` and surfaces a clear 401 message;
`background.ts` loads the token from `chrome.storage.local` and tracks changes; the popup
(`popup.html/.ts/.css`) gained a paste-to-pair field.

Tests: `LocalApiSecurityTests`, `ApiHostLifecycleServiceTests` (rewritten with a fake settings
service to cover disabled/first-run/reuse-token paths).

## 2. Backup restore path containment + zip-bomb caps (#2, High)

New `PathHelper.ResolveContainedPath` / `TryResolveContainedPath` / `IsSafeRelativeEntry` /
`IsPathContained` — the canonical, **fail-closed** containment guard (the pre-existing
`GetRelativePath` returns-on-fail and is unsafe as a boundary). `BackupService`:
- restore loop resolves each `documents/` entry through `ResolveContainedPath` (throws → rolls back);
- `ValidateBackupAsync` rejects traversal/rooted/oversize entries up front via a new public, testable
  `TryValidateDocumentEntries`;
- `CopyEntryWithLimitAsync` enforces a per-file cap; a running total enforces an aggregate cap
  (generous defaults: 2 GB/file, 50 GB total).

Tests: `BackupServiceSecurityTests`, `PathHelperContainmentTests`.

## 3. Plugin manifest + path hardening (#3, High)

`PluginManifestValidator` is now injected into `PluginService.InstallPluginAsync` (it was registered
in DI but unused) and tightened: strict reverse-DNS plugin ID (rejects `..`, separators, reserved
device names) and a **bare-`.dll`** entry assembly (`PathHelper.IsBareFileName`). Defense-in-depth
containment added to `GetPluginInstallPath`, `GetEntryAssemblyName`, the activation load
(`EnablePluginAsync`), and the uninstall recursive delete. The existing `ExtractPackageAsync`
already had a correct zip-slip guard (left in place).

Tests: `PluginManifestValidatorSecurityTests` (existing `PluginManifestValidatorTests` stay green).

## 4. WebSearchApiKey encryption (#4, Medium)

`SettingsService` routes `WebSearchApiKey` through `EncryptIfNotEmpty` on save and
decrypt/auto-migrate on load — identical to OpenAI/Anthropic/OAuth secrets. Tests added to
`SettingsServiceEncryptionTests`.

## 5. Web-fetch bounded read (#5, Med/Low)

`WebContentFetcher.FetchHtmlInternalAsync` keeps the early `Content-Length` check but now reads the
body through `ReadBoundedAsync`, which counts bytes and aborts past `MaxContentLengthBytes` (10 MB)
even when the header is missing/lying; decoding respects the response charset. Tests:
`WebContentFetcherSizeLimitTests` (stub `HttpMessageHandler` + custom `HttpContent`).

## 6. Backup authenticated encryption (Additional Notes)

`BackupService.EncryptBytes` now produces **AES-256-GCM** (V2 magic `AGXENC2\0`: salt+nonce+tag+ct);
`DecryptBytes` dispatches by magic and still decrypts **legacy CBC** (`AGXENC\0\0`) archives. GCM
authentication means a wrong password or tampered archive is rejected before restore. Tests cover
round-trip, tamper rejection, wrong-password, and legacy-CBC restore.

## 7. Extension npm audit

`npm audit fix` resolved `brace-expansion` + `fast-uri`; `copy-webpack-plugin` bumped to `^14`
cleared the `serialize-javascript` chain (its `patterns` API is unchanged; v14 only raises the
Node/webpack floor we already meet). `npm audit` → **0 vulnerabilities**; lint/typecheck/build green.

## 8. Mobile companion follow-up (commit 2)

The desktop API is now authenticated for **all** clients, so `AgentX.Mobile` (which calls
`/api/health`, `/api/documents`, `/api/conversations`, `/api/collections`, `/api/search`) would have
returned **401 everywhere**. Fixes:
- `AgentXApiClient` sends `Authorization: Bearer`; `SetToken()` applies/clears it and it survives
  `SetBaseUrl()` rebuilds.
- mobile `SettingsService` stores the token in **`SecureStorage`** (platform keystore — the mobile
  parity of desktop DPAPI), not plain `Preferences`.
- `SettingsViewModel`/`SettingsPage` add an **API Token** field; Save persists + applies it; Test
  Connection uses it; `App.OnStart` applies the stored token before the data pages load.

> ⚠️ **Not compile-built this session.** `AgentX.Mobile` targets `net8.0-android;net8.0-ios`, is
> **not part of `AgentX.sln`** (so it cannot affect the Codex gate), and the build needs the
> `maui-android` / `maui-ios` workloads — not installed here (iOS also needs macOS). These changes
> were verified by **review** against the existing MAUI/CommunityToolkit.Mvvm patterns. To
> compile-verify: `dotnet workload install maui-android` then
> `dotnet build src\AgentX.Mobile\AgentX.Mobile.csproj -c Release -f net8.0-android`.
